## Overview

As part of the ASCTE 301/401 curriculum, our team designed a distributed weather monitoring system. My component was the programming to run the backend and the sensor node — collecting environmental data and sending it to a central aggregator to be processed and stored.

## Goals

- Read temperature, humidity, and barometric pressure from physical sensors
- Format and transmit data to a central system securely
- Handle edge cases (sensor failure, connection drops) gracefully
- Store data in a database for future retrieval
- Create a website hosted on the server to securely allow access to weather sensor data
- Document all code and cybersecurity implementations

## Tools & Skills Used

- **Embedded programming** — reading data from physical sensors
- **API Architecture** — writing an API to handle sensor data and host a website gracefully and safely
- **Systems thinking** — designing one component to fit into a larger architecture
- **Secure Programming** — learning and implementing cybersecurity protections such as rate limiting, api key authentication, hashing user passwords, and preventing unauthorized access
- **Thorough Documentation** — Explaining and writing each detail and the conveying the importance of it for my peers to understand

## What I Learned

Working on one piece of a larger system meant I had to think beyond my own component — the program I wrote had to work with the computer and sensors that my team designed. This project taught me the importance of communication and documentation when multiple people are building different parts of the same thing.
